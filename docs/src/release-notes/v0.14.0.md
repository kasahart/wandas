# Wandas 0.14.0

Wandas 0.14.0 cuts out trigger events across every recording of a Dataset in
one call, and makes reading part of a cached Frame cheap: a slice of a
`cache()` result copies only the selected samples instead of every channel.

Wandas 0.14.0では、Datasetの全録音からトリガーのイベントを1回の呼び出しで切り出せるようになり、
キャッシュしたFrameの一部を読むときの負担が小さくなりました。`cache()`の結果の一部を読むと、
全チャンネルではなく選んだサンプルだけをコピーします。

## Highlights / 主な変更

- `ChannelFrameDataset.trigger()` returns one Dataset of the trigger events of
  every recording, each with its recording's metadata.
  `ChannelFrameDataset.trigger()`は全録音のトリガーのイベントを1つのDatasetで返し、
  各イベントは元の録音のmetadataを持ちます。
- Reading one slice of a cached Frame, such as `frame.cache()[:, a:b].data`,
  copies only that slice. Before, every read first copied the whole cached
  channel blocks. Values do not change, and the arrays you get back are still
  writable copies that do not change the cache.
  `frame.cache()[:, a:b].data`のようにキャッシュしたFrameの一部を読むと、その部分だけをコピーします。
  これまでは読むたびに、まずキャッシュしたチャンネルのブロック全体をコピーしていました。値は変わらず、
  返る配列は今までどおり書き込み可能なコピーで、書き換えてもキャッシュは変わりません。

## Added / 追加

- `ChannelFrameDataset.trigger()` cuts out level-trigger events across every
  recording of a Dataset and returns one Dataset of all hits. Each hit keeps
  its recording's metadata plus `trigger_index` and `trigger_time`
  ([#589](https://github.com/kasahart/wandas/issues/589)). Detection loads
  every recording's trigger channel, so this call is not lazy per item; the
  segments stay lazy time slices.
  `ChannelFrameDataset.trigger()`で、Datasetの全録音からレベルトリガーのイベントを切り出し、
  全ヒットを1つのDatasetで返します。各ヒットは元の録音のmetadataと`trigger_index`・`trigger_time`を
  持ちます。検出のために全録音のトリガーチャンネルを読み込むので、この呼び出しは項目ごとの遅延評価では
  ありません。切り出した区間は遅延評価のままです。

## Compatibility and migration / 互換性と移行

This release has no compatibility change; `ChannelFrameDataset.trigger()` is additive. Computed values, Recipe
schemas, operation versions and WDF formats do not change. The samples kept
by `cache()` are now read-only internally, but `data`, slices,
`np.asarray()`, `apply()` and `AudioOperation` kernels still receive writable
arrays, and writing into them never changes the cache.

このリリースに互換性の変更はありません（`ChannelFrameDataset.trigger()`は追加のみです）。計算結果・Recipeのスキーマ・操作のversion・WDFの形式は
変わりません。`cache()`が内部に保持するサンプルは読み取り専用になりましたが、`data`・スライス・
`np.asarray()`・`apply()`・`AudioOperation`のカーネルは今までどおり書き込み可能な配列を受け取り、
書き換えてもキャッシュは変わりません。
