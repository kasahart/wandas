# Wandas 0.13.0

Wandas 0.13.0 lets you save a level-trigger analysis as a Recipe. A Recipe
records the trigger conditions and the events you dropped or kept, so
replaying it on another recording finds that recording's events again and
averages them the same way. It also adds peak and kurtosis of a signal,
peak picking on spectra, spectral kurtosis and time integration.

Wandas 0.13.0では、レベルトリガーの解析をRecipeとして保存できるようになりました。Recipeにはトリガーの
条件と除いた・残したイベントを記録するので、別の録音で再生するとその録音のイベントを検出し直して同じように
平均します。信号のピーク値と尖度、スペクトルのピーク検出、スペクトル尖度、時間積分も追加しました。

## Highlights / 主な変更

- `RecipePlan.from_frame(cf.trigger(10.0, duration=1.0, pre=0.01).drop([2]).transfer_function())`
  works: `trigger()`, `segment()`, `drop()`, selections and the averages of
  `ChannelFrameSegments` are Recipe steps.
  `trigger()`・`segment()`・`drop()`・選択と`ChannelFrameSegments`の平均がRecipeのstepになり、
  上の式のRecipeを保存・再生できます。
- `cf.peak` / `cf.kurtosis`, `cf.welch().find_peaks()`,
  `cf.stft().spectral_kurtosis` and `cf.integrate()` (for example acceleration
  to velocity) are new.
  `cf.peak`・`cf.kurtosis`、`cf.welch().find_peaks()`、`cf.stft().spectral_kurtosis`、
  `cf.integrate()`（例: 加速度から速度）が加わりました。

## Compatibility and migration / 互換性と移行

Computed values of existing operations do not change. Recipes with the new
steps (including `integrate()`) need 0.13.0 to load: 0.12.0 and earlier reject
them at load time. Spectrograms from `stft()` now save as WDF 0.7, which 0.12.0
and earlier reject. The `operation_history` of
`ChannelFrameSegments` results, which WDF files also store, now lists the
trigger, drop or select and average steps instead of one `join` or `average`
step with an input per segment.

既存の操作の計算結果は変わりません。新しいstep（`integrate()`を含む）を含むRecipeの読み込みには0.13.0が
必要で、0.12.0以前は読み込み時に拒否します。`stft()`のスペクトログラムはWDF 0.7で保存され、0.12.0以前は
読み込みを拒否します。`ChannelFrameSegments`の結果の`operation_history`（WDFにも保存されます）は、セグメントごとの
入力を持つ1つの`join`・`average`の代わりに、トリガー・除外または選択・平均のstepを並べます。

## Added / 追加

- Level-trigger workflows can be saved and replayed as Recipes
  ([#630](https://github.com/kasahart/wandas/issues/630)). `ChannelFrame.trigger()`
  and `segment()`, `drop()`, selections by index, slice or mask (recorded as
  the event IDs they keep), and `average()`, `transfer_function()` and `coherence()` of
  `ChannelFrameSegments` are Recipe steps, so
  `RecipePlan.from_frame(cf.trigger(10.0, duration=1.0, pre=0.01).drop([2]).transfer_function())`
  works. A Recipe records the trigger conditions, not the detected positions:
  replaying it on another recording detects that recording's events again, and
  drops or keeps the events with the same IDs there. Segments now carry a `lineage` like
  a Frame, and each segment's Frame keeps its own lineage as a time slice of the
  source. `apply(func)` and segments built
  directly from Frames still cannot be saved, with a message that says why. A
  Recipe's inputs, output and named steps stay Frames; segments only appear
  between its nodes. `default_recipe_registry().describe()` lists the new steps
  with `ChannelFrameSegments` or `FrameSegments` as their receiver or result.
  レベルトリガーの処理をRecipeとして保存・再生できるようになりました。
  `ChannelFrame.trigger()`と`segment()`、`drop()`、位置・スライス・マスクによる選択（残すイベントIDとして記録）、
  `ChannelFrameSegments`の`average()`・`transfer_function()`・`coherence()`がRecipeのstepになります。
  Recipeには検出した位置ではなくトリガーの条件を記録するので、別の録音で再生するとその録音で
  検出し直し、同じIDのイベントを除く・残します。Segmentsも Frame と同じく`lineage`を持ち、各セグメントの
  Frameは元の録音の時間スライスとして自分のlineageを保ちます。`apply(func)`と
  Frameから直接作ったSegmentsは今までどおり保存できず、理由をメッセージで示します。Recipeの入力・
  出力・名前付きstepはFrameのままで、Segmentsはnodeの間にだけ現れます。
- `ChannelFrame.peak` and `ChannelFrame.kurtosis` return the peak absolute
  value and the Pearson kurtosis of each channel as NumPy arrays, like `rms`.
  `kurtosis` uses `dask.array.stats.kurtosis`.
  `ChannelFrame.peak`と`ChannelFrame.kurtosis`は、`rms`と同じように各チャンネルの絶対値の最大と
  ピアソンの尖度をNumPy配列で返します。`kurtosis`は`dask.array.stats.kurtosis`で計算します。
- `SpectralFrame.find_peaks()` lists the spectral peaks of each channel as a
  pandas table (frequency, level, amplitude, prominence), using
  `scipy.signal.find_peaks` on the dB level, with optional parabolic
  interpolation between bins.
  `SpectralFrame.find_peaks()`は、dBレベルに`scipy.signal.find_peaks`を使って各チャンネルのスペクトルピーク
  （周波数・レベル・振幅・突出度）をpandasの表で返します。ビン間の放物線補間も選べます。
- `SpectrogramFrame.spectral_kurtosis` returns the spectral kurtosis of each
  channel over time, aligned with `freqs`, to find the band where impulses
  are strongest.
  `SpectrogramFrame.spectral_kurtosis`は各チャンネルの時間方向のスペクトル尖度を`freqs`に揃えて返します。
  衝撃成分が最も強い帯域を探すのに使えます。
  Only the STFT frames that lie wholly inside the signal are used; the new
  `SpectrogramFrame.signal_length` records the analysed length for this.
  信号の内側に収まるSTFTフレームだけを使います。そのために解析した信号の長さを新しい`SpectrogramFrame.signal_length`に保持します。
  Spectrograms from `stft()` therefore save as WDF 0.7, which Wandas 0.12.0 and
  earlier cannot read.
  そのため`stft()`のスペクトログラムはWDF 0.7で保存され、Wandas 0.12.0以前では読めません。
- `ChannelFrame.integrate()` integrates each channel in time with the
  trapezoidal rule, for example acceleration to velocity, and moves the unit
  along `m/s^2 -> m/s -> m`. It is a Recipe step. Remove the drift with
  `high_pass_filter()` afterwards.
  `ChannelFrame.integrate()`は各チャンネルを台形則で時間積分し（例: 加速度から速度）、
  単位を`m/s^2 -> m/s -> m`と進めます。Recipeの手順として記録されます。
  ドリフトは後から`high_pass_filter()`で取り除きます。

## Changed / 変更

- The `operation_history` of `ChannelFrameSegments` results (and the history a
  WDF file stores for them) changes with
  [#630](https://github.com/kasahart/wandas/issues/630): instead of
  `wandas.segments.join` or `wandas.segments.average` with one input per segment
  and an `event_ids` parameter, it lists `wandas.audio.trigger` or
  `wandas.audio.segment`, then `wandas.segments.drop` or `wandas.segments.select`
  for excluded or selected events, then `wandas.segments.average`,
  `wandas.segments.transfer_function` or `wandas.segments.coherence`. The computed values do not change.
  `ChannelFrameSegments`の結果の`operation_history`（WDFに保存される履歴も）が変わります。
  セグメントごとの入力と`event_ids`を持つ`wandas.segments.join`/`average`の代わりに、
  `wandas.audio.trigger`または`segment`、除外・選択の`wandas.segments.drop`/`select`、
  `wandas.segments.average`・`wandas.segments.transfer_function`・`wandas.segments.coherence`が並びます。計算結果は変わりません。
